- **Qwen3-Omni (open-source) DOES support translation as a prompt-driven task.** The GitHub README lists an official cookbook "Speech Translation — Speech-to-Text / Speech-to-Speech translation", and the eval section defines a prompt: `Listen to the provided <source_language> speech and produce a translation in <target_language> text.` — https://github.com/QwenLM/Qwen3-Omni (README) and `cookbooks/speech_translation.ipynb`. So: audio in → translated text out, and audio in → translated audio out (S2ST), but this is emergent capability via prompting, **not** a documented API feature/parameter.
- **Exact Omni-Realtime model IDs** (from the realtime doc, retrieved today): `qwen3.8-omni-flash-realtime` (current flagship; 196608 input token cap; 100 audio turns / 600 s), `qwen3.5-omni-plus-realtime`, `qwen3.5-omni-flash-realtime` (80 turns / 480 s), plus snapshot `qwen3-omni-flash-realtime-2025-09-15`. Note the IDs you guessed (`qwen3.8-omni-flash-realtime`, `qwen3.5-omni-plus-realtime`) are correct; there is no `qwen3.5-omni-plus-realtime`-style "translate" variant.
- Offline/non-realtime Omni IDs: `qwen3.8-omni-flash` (text out only), `qwen3.5-omni-plus` / `qwen3.5-omni-flash` (speech out).

## 3. Alibaba simultaneous interpretation (同声传译) API → **YES**

**Name: Qwen-LiveTranslate-Realtime** (千问实时语音/音视频翻译). Chinese doc explicitly uses **同传** and states "低至 2.3 秒的同传时延". This is a purpose-built simultaneous-interpretation API, separate from Omni.

**Exact model IDs:**
- `qwen3.8-livetranslate-flash-realtime` (stable, current; source language auto-detected, always-on source transcription)
- `qwen3.5-livetranslate-flash-realtime` (stable alias of `qwen3.5-livetranslate-flash-realtime-2026-05-19` snapshot)
- Both: 53248 context / 49152 max input / 4096 max output tokens.

**Protocol / endpoint:**
- WebSocket: `wss://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/api-ws/v1/realtime?model=<model>` (Singapore: `...ap-southeast-1...`); auth header `Authorization: Bearer DASHSCOPE_API_KEY`
- Also supported: **AOQ** (AI-over-QUIC; recommended for Android clients — built-in AEC/noise suppression, native Android/iOS/HarmonyOS) and **WebRTC** (`POST https://{WorkspaceId}...maas.aliyuncs.com/api/v1/webrtc/realtime`, SDP)
- Session events: `session.update`, `input_audio_buffer.append`, `input_image_buffer.append` (optional images), `session.finish`; outputs `response.text.delta` / `response.audio.delta` / `response.audio_transcript.delta`; speaker diarization via `speaker_id`.
- **Capabilities:** 60 languages (29 audio+text output, incl. zh/en/fr/de/ru/ja/ko/es/pt/ar; 31 text-only), 2.3 s latency, real-time speaker separation, "lossless" simultaneous interpretation, hotwords (`session.translation.corpus.phrases`), **voice cloning** (real-time, no extra cloning fee; the cloned-voice id format seen in docs is `qwen-translate-vc-xxx-yyy-zzz`), visual enhancement from images (≤2 images/sec).
- **Limitations:** `session.finish` MUST be sent before closing or the last segment is lost; `qwen3.5-...` uses `response.text.text` (not `response.text.delta`) which differs from Omni event semantics and must not be mixed; 1000-hotword guidance.
- Sources: https://help.aliyun.com/zh/model-studio/qwen3-5-livetranslate-flash-realtime (EN: https://help.aliyun.com/en/model-studio/qwen3-5-livetranslate-flash-realtime) , client events https://help.aliyun.com/en/model-studio/live-translator-client-events , server events https://help.aliyun.com/en/model-studio/live-translator-server-events , protocol overview https://help.aliyun.com/en/model-studio/realtime-api-overview

## 5. Is there a speech-translation API separate from Omni? → **YES**

Two separate paths: (a) **Qwen-LiveTranslate-Realtime** — a fully separate real-time simultaneous-interpretation model family (not Omni); (b) **Qwen-MT-Uni** accepts audio (3 s–60 min) and outputs translated text/audio, but in sync/async batch mode, not streaming. The "语音转语音" product category also lists `qwen-audio-3.1-realtime-plus` (end-to-end voice chat, not a translation product).
